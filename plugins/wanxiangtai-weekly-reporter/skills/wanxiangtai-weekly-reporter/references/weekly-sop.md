# 每周追加 SOP

## 1. 解析短指令

把用户日期转换为完整的 `YYYY-MM-DD` 起止日期，并生成显示标签 `M.D-M.D`。只有年份不明确且跨年会改变结果时才询问。单一有效品牌配置自动选用；多个配置才询问品牌。

先运行 `run_manifest.py start`：

- 同品牌、同起止日期已完成：停止，报告已存在，不能重复写入。
- 存在未完成任务：从第一个非完成计划继续。
- 新周期：创建任务清单，状态为 `in_progress`。

## 2. 检查计划映射

读取万相台当前可见计划并与 profile 比较。已有 campaign ID 使用稳定映射；新计划只确认新增项。计划消失时标记为 `not_visible` 并报告，不把其他计划误配过去。

## 3. 单计划浏览器事务

1. 点击左侧准确计划名，核对 URL campaign ID 和起止日期。
2. 读取计划总计：展现、CR、CTR、直接成交金额、花费、总 ROI。
3. 点击“全部展开”，以包含“素材ID”的创意行作为稳定边界。
4. 按页面顺序提取每一行：素材名、素材 ID、类型、媒体地址及六项指标。
5. 素材行可有相同 ID；若网页是不同记录或指标不同，全部保留。
6. 校验网页行数等于结构化记录数，并确保每条媒体地址非空。懒加载地址为空时滚动到对应区段后补读。
7. 立即把原始 JSON 写入本周期目录。未落盘前不进入下一个计划。

浏览器调用保持短小：一次导航、一次汇总读取、一次展开、一次素材读取。相同连接故障只轻量恢复一次，不循环重试。

## 4. 素材与方向

1. 下载图片；视频保存地址并抽取代表帧。下载失败必须逐条报告，不得跳过该素材。
2. 素材日期从名称中明确的月日数字提取；无法识别时留空并在备注列记录名称和 ID。
3. 方向只允许：用户信任、圈人群、正向、反向、功能、情感价值、使用感受、使用结果。
4. 相同素材可复用历史方向，但历史值必须全部属于合法枚举；新素材依据画面和文案判断。
5. 图片和视频分别选择一个最佳素材。直接 ROI 为主，同时检查成交、花费和展现规模，排除极低消耗的偶然高值。

## 5. 追加写入

1. 使用 `find_next_block.ps1` 查找下一空白块并检测同周期是否已存在。
2. 比较 `max(图片数, 视频数)` 与当前素材容量。容量不足时先运行 `invoke_expand_sheet_capacity.ps1`，备注列随之右移。
3. 第一周期使用已有空模板块；后续周期使用 `invoke_initialize_append_block.ps1` 从第一块复制格式和标签。
4. 使用 `invoke_write_plan_to_lark.ps1` 写值、公式、多选方向、封面和最佳素材高亮。
5. 所有写入先通过 dry-run；目标块非空时停止，禁止使用覆盖参数绕过。

素材数量没有业务上限。飞书单表达到物理列上限时，新建 `<工作表名>__素材续表N`，沿用同周期和字段结构，并在主表备注写入续表名；不得静默丢弃素材。

## 6. 验证与进度

每个计划写完必须回读：

- 计划名、周期和六项汇总。
- 图片、视频的页面行数与表格列数。
- 封面、视频地址、类型、方向。
- 直接 ROI 公式及计算结果。
- 图片和视频各自最多一个最佳高亮。
- 所有历史周期的值与结构未变化。

验证通过后才把计划标为 `completed_and_verified`。全部计划完成后执行全局只读复核，并用 `run_manifest.py complete` 将状态改为 `complete_and_globally_verified`。
