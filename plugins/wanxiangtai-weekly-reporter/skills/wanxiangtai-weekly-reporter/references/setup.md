# 首次初始化

首次初始化的目标是：使用客户自己的登录和飞书空间创建标准周报，确认一次计划映射，并保存不含凭据的本地品牌配置。

## 前置检查

1. 确认 Windows 可用 `python`、`pwsh`、`lark-cli` 和 `codex`。
2. 万相台必须已在 Chrome 登录。不得要求用户发送密码、Cookie 或 Token。
3. 运行 `lark-cli auth status`。未配置时按当前 `lark-shared` 规则发起最小权限用户授权；授权链接和二维码只交给当前用户。
4. 品牌配置默认保存到 `~/.codex/wanxiangtai-weekly-reporter/profiles/`，不得提交到插件仓库。

## 发现并确认计划

1. 在专用受控 Chrome 标签打开万相台“人群推广”。
2. 只读取当前账号可见计划，提取完整计划名和 campaign ID。
3. 生成建议工作表名时，只把名称中的“人群推广”视为可省略的业务词；保留下划线和其他字符，不做固定前缀盲删。
4. 向用户展示 `万相台计划名 → 工作表名`。只在首次建立映射、新计划出现或名称冲突时请求确认。
5. 映射必须满足 campaign ID、源计划名和工作表名一一对应。

计划映射文件示例：

```json
[
  {
    "campaign_id": "123456789",
    "plan_name": "人群推广_示例计划_内容智能出价",
    "sheet_name": "示例计划_内容智能出价"
  }
]
```

## 创建飞书周报

1. 先运行 `create_brand_workbook.ps1` 的默认 dry-run，检查计划数量、素材容量和操作结构。
2. 用户已明确要求初始化并创建表格时，使用 `-ConfirmWrite` 创建工作簿。创建中途失败时保留返回的工作簿 token 并修复，不自动删除工作簿。
3. 每个计划对应一张可见工作表；保留隐藏的 `_周报模板` 供新增计划复制。周报流程永远忽略隐藏模板。
4. 默认预留 24 个素材列；实际素材更多时在备注列前扩列，不能截断。
5. 通过 `+workbook-info` 回读所有工作表 ID、标题、隐藏状态和列数，生成最终映射。

## 保存品牌配置

使用 `profile_manager.py init` 保存配置。配置中只允许工作簿 token、工作表 ID、计划 ID、名称、排除项、模板参数和本地数据目录，不得写入账号凭据。

保存后运行：

```powershell
python scripts/profile_manager.py validate --profile <profile-id>
```

## 首次验收

选择一个计划和一个短日期范围，完整执行一次抓取、素材处理、写入和回读。样本必须通过后才批量处理其他计划。初始化完成的证据包括：

- 品牌配置验证通过。
- 工作簿及计划工作表数量正确。
- 样本计划周期、六项汇总、全部素材、公式、方向和高亮均通过。
- 重新运行同周期时被重复周期保护拒绝。
